# Paper2Lab · 论文—代码—实验结果 智能一致性审计平台

**把「论文说了什么 / 代码在跑什么 / 实测得到什么」三方交叉核验，给出每条都能回溯出处的结论。**

每个值都能追到 `文件:行号` 或 `Page N`；拿不准的一律如实说「未取到 / 未核验」。
一句话设计原则：**确定性的判定交给程序，需要取舍的提议交给 AI，否决权留在程序手里。**

`Python 3.13` · `Streamlit` · `PyMuPDF` · `OpenAI 兼容大模型` · `AST 静态分析` · `化学规则引擎` · `42 项自动化回归`

---

## 一、这是什么

### 痛点：复现失败，多半不是"不会跑"，而是"配置对不上"

`1e-4` 对 `1e-3`、随机种子没固定、数据集差一个版本、论文写 94.3% 而实测 91.7%……
**这些差异一个都不报错，只让结果悄悄不一样。** 人工逐项核要几个小时，而且极易漏。

数据背景：Nature 2016 调查显示，**>70%** 的研究者复现他人实验失败过，**>50%** 连自己
做过的实验都复现不了，却只有 **<20%** 的人被同行反馈过；ML 顶会 400 篇论文（2018）
没有一篇满足全部可复现标准，平均只满足 20–30%。

### 关键判断：瓶颈已经转移

复现问题分三层，前两层已有成熟手段，**第三层至今没有自动化工具**——

| 层次 | 问题 | 现状 |
| --- | --- | --- |
| ① 材料层 | 作者有没有公开代码？ | 措施已很多，代码可用率已达 **74.4%** |
| ② 运行层 | 能不能跑起来？ | 工具链成熟（容器 / 环境管理） |
| ③ **一致性层** | **论文声明的配置，与代码实际实现是否一致？** | **只能人工逐项核 → 本项目在这里** |

### 面向谁

复现者（核对几小时到几天，还不知道漏了什么）· 审稿人 · 论文作者 · 团队落地者。

## 二、核心功能

### 1. 三方交叉核验，每条结论都带证据

三个输入：论文 PDF（必需）、代码 ZIP（可选）、实验结果 JSON（可选）。
系统抽出三方的参数与指标，做数值归一化后逐项比对，**每条结论都带出处**：

- 论文侧 → `Page N · Section`（如 `Page 3 · 4.1 Training`）
- 代码侧 → `file.py:行号`（如 `train.py:53`）
- 实测侧 → 用户提供的 `results.json` 键值

`results.json` 是**第三类数字**——"你机器上真跑出来的那个"。代码包里 README 的成绩表
属于**作者自己的声明**，与论文声明同源，拿它做对照不构成复现核验，所以系统**只认**这份 JSON：

```json
{ "accuracy": 81.89, "f1": 0.92, "loss": 0.38 }
```

支持的指标键：`accuracy` / `f1` / `precision` / `recall` / `loss` / `silhouette`。
判定口径：相对差异 ≤1% 视为一致；≥5%（或绝对差 ≥2 个点）为高风险。
**只在论文也声明了同名指标时才核验**，不拿不可比的口径硬比。

### 2. 四条抽取通道，各自标注置信度

| 输入 | 通道 | 精度 | 结论标记 |
| --- | --- | --- | --- |
| Python / Jupyter Notebook | **AST 精确解析**（带作用域语义，天然忽略注释与字符串） | 高 | 🧩 |
| MATLAB / R / Julia / C-C++-CUDA / Java / Fortran / Shell / INI / TOML | **多语言通用通道**：逐行识别 `name = value` / `name <- value` / `name: value`，仍带 `文件:行号` | 中 | 🔧 通用通道 |
| PDF 三线表 / 参数表 | **表格通道**：`find_tables()` 结构化为「参数名→值」，证据为 `Page N · 表格 k` | 中 | 📊 表格通道 |
| PDF 图片 / 扫描页 | **图像通道**：视觉大模型读图，双次独立读取取交集 | 低-中 | 👁️ Inferred（**不计入就绪度**） |

第四条通道（读图）无法用文本层验证，因此换用**三道保险**：

1. **AI 只提议**——视觉模型必须返回严格 JSON，每个参数附「图中原文片段」；
2. **双次独立读图取交集**——同一区域问两次，两次不一致的值直接丢弃（防幻觉）；
3. **结论降级**——标 `👁️ Inferred`、**不参与就绪度评分**、单列「请人工核对原图」。

未配置视觉通道时系统**如实提示**「发现 N 个图片/扫描区域，图像通道未启用，这些区域未参与审计」，
不会假装审过。逐行解析不了的文件（语法错误、不支持的格式）会进**解析失败示众清单**
（文件名 + 原因 + 行数），不再静默跳过。

### 3. 审计的审计：每条结论本身还要过三道关卡

系统不只审计别人，**每条结论本身也要过三道独立关卡**：

| 关卡 | 机制 | 防的是什么 |
| --- | --- | --- |
| ① 合理性先验校验 | 参数值超出领域先验范围（`lr∈(0,1)`、batch 为正整数…）直接拒收并示众 | 错位抽取（把年份 2024 当学习率） |
| ② 证据自证 | 每条证据的 `snippet` 必须真的包含其 `raw_value`；页码 / 行号必须真实存在 | 「页码对但值串了」、行号编造 |
| ③ 结论复算 | 出具结论前用同一套归一化逻辑重新比一遍，必须与 status 一致 | 「没核对却说核对了」 |

另有**内部一致性交叉核对**：论文内部 / 代码内部多处声明互查，判的是「这真的是矛盾吗」。
论文侧只有**同页、同章节、其余细节一致却给了两个值**才判「内部不一致」——
按任务/阶段分别给参数是论文常规写法，这类只出一条「多处取值」提示，不判错；
代码侧看**会不会在同一次运行里同时生效**：同一个文件、同一目录下的入口脚本与配置、
根目录平铺 → 判「内部不一致」（配置被覆盖是真问题）；分处不同任务目录、或落在
`experiments/` 这类「一个文件一套实验」的目录 → 只出一条「多套配置」提示。
灵敏度分析、分组实验语境自动豁免。

### 4. 两个分数，不混用

| 分数 | 评价对象 | 构成 |
| --- | --- | --- |
| **复现就绪度**（0-100） | **被审对象**的可复现程度 | 起始 100，高风险 −15、中风险 −8、低风险 −3 |
| **审计可信度**（高/中/低） | **本次审计过程**的覆盖率与可靠程度 | 页级文本覆盖率、疑似声明覆盖率、代码解析成功率、自检通过率 |

覆盖率不足时可信度会明确变低——**系统不假装"都审过了"**。

**「未核验」是显式状态**：一个维度只有在**真的做了比对**时才给分；没有可比对象时标注
「未核验」，**不给分、也不进总分**。修这条之前的行为是**误导性**的——不提供实测结果时，
「结果一致性」走默认值显示 **100 分（绿色）**，「实验记录完整度」固定给 **60 分**，
等于把"用户没上传"算成论文的问题，而且方向是反的（做了核验反而分更低）。

### 5. 抽取 Agent：有界重试闭环

针对系统最薄弱的一环——**「论文提到但没取到值」的漏抽**——加了一个**有界重试闭环**，
每个待补参数按阶梯逐级尝试（从便宜到贵）：

```
text-l1   同句紧邻（"100K iterations"）              —— 零成本
text-l2   同句近距离（"Our 32 × 32 models ..."）      —— 零成本
negation  论文提到"不使用该参数" → 只作提示，不判定取值
llm       LLM 提议取值 + 程序回原文核对
vision    只读"提到该参数的页" + 两次独立读取取交集
```

**三道边界**（缺一不可，都是被实测误报逼出来的）：

1. **预算**：每轮最多 3 次 LLM 调用 / 2 次视觉调用 / 45 秒，超限即停并如实记录；
2. **闸门**：任何候选都要过——回原文核对 + 取值在证据中 + 合理性先验 + 形状守卫
   （`input_size` 必须有 `N×N`）+ 语义守卫（`keep ratio 0.7` ≠ dropout `0.7`）
   + 区间守卫（`100–300k` 是收敛范围不是设置）+ 编号守卫（`图2 模型` 里的 2 是图号）
   + **分布参数守卫**（`rng.normal(0.0, sigma, N)` 里的 `0.0` 是分布均值，不是随机种子）；
3. **轨迹**：每次尝试都记录「做了什么 / 结果 / 被拒原因」，写入报告与页面，可回放。

> 实测（五套真实论文，Agent 开/关对比）：未取到的参数种类 **5 类 → 4 类**。
> 数字不大，但更有价值的是 **Agent 挡下了 3 条看似合理实则错误的候选**
> （收敛范围当设置、keep ratio 当 rate、调度周期当总轮数），全部留痕并转人工核查。
> **宁可不报，也不报一个可能错的值。**

### 6. 工具箱 ＋ 规划调度：15 环节 / 14 件工具

把流水线的每一站登记成**可单独调用的工具**，每个工具声明自己的依赖产物、产出产物、
成本与覆盖的进度节点。**十五个进度节点由十四件工具完成**（其中「化学身份核验」不单独占格——它是"读"这一步的一种视野，与闭环复算同款口径）——「参数归一化 / 交叉匹配 /
实验结果核验」在实现上是 `aligner.align` 的三段职责，一次遍历同时产出，不做无意义的硬拆。
四站因而都有真实环节：① 假设 6 格 · ② 实验 1 格 · ③ 验证 5 格 · ④ 迭代 3 格。

**规划与调度由模型主导**（1C 起）：模型看材料的实际情况（有没有代码包、有没有实测结果、
有没有配置读图通道、论文多少页），排一份「本次跑哪些、跳过哪些」的计划，**每条决策都带理由**，
结果页的「执行记录」面板把计划与实际执行逐条对照。**程序不设闸门**，只有两个例外：
① 模型不可用时自动回退规则版，并**如实标注** `planner="rule"`（不假装模型排过）；
② 「参数对齐与结果核验」——它是唯一产出结论的一步，被跳过整轮就没有结论，故按**底线兜底**保下来。

**为什么保留规则版**：零成本、可复现（同一份材料永远排出同一份计划）、可作消融对照。
它是**兜底**而非主路径——模型不可用时顶上，等价性回归也靠它比对。

**只有一条路：先排计划、再执行**（2026-10-25 按用户口径删除「经典模式」）。

| 情形 | 行为 |
| --- | --- |
| **模型可用** | 模型看材料排计划：材料齐备时跑满十五个环节，不齐备时只跑对应环节并**逐条说明理由** |
| **模型不可用** | 自动回退**规则版计划**（同样按材料排，只是不调模型），并**如实标注** `planner="rule"` |

为什么删掉"固定全序全跑"：它会把"没有代码也扫一遍代码"这种无效动作固化下来，
让同一份材料出现两条结论口径。要证明"调度没改结论"，现在靠的是
**同一份材料跑两遍、计划与结论必须一模一样**（`tests/verify_ablation_modes.py`），
不再需要一个全跑对照组。

#### 6.1 ② 实验站的九件计算工具：换算器 ＋ 计算器

② 站是唯一动手算数的地方，它手里的工具分两批，**解决的问题不同，不是重复建设**：

| 批次 | 工具 | 解决什么 |
| --- | --- | --- |
| **换算器**（2D，五件） | 单位展开 / 算术求值 / 合法区间检查 / 倍数探测 / 关系式复算 | 「同一个数，两种写法」——比大小、换单位、代公式 |
| **计算器**（3A，四件） | 浮点精度 / 序列统计 / 直线最小二乘 / 峰位定位 | 「**这串数本身说明什么**」 |

四件计算器各自对应一类真实翻车：

- **浮点精度**：论文写 `lr=1e-8`、代码默认半精度——这个数在半精度里**直接落成 0**，
  等于没设学习率，而且**不报错、训练照跑**。阈值取 IEEE-754 规格值（最小非零数 `2⁻²⁴≈5.96e-8`），
  不是拍脑袋定的「看起来很小」。同一个值换到单精度就正常——所以它认的是规格表，不是一句套话。
- **序列统计**：论文说「5 次运行方差很小」——把值拿出来算**样本**标准差（除以 n−1 而非 n，
  否则 n=3 时系统性偏小约 20%）。取值不够 2 个就如实说「本次拿不出证据」，不硬凑一个 0 方差。
- **直线最小二乘**：论文常说「精度随数据量线性增长」，但常常只有 3 个点。拟合出的 R² 就是
  这句话的**可证伪性**——说线性而 R²=0.64，就该被记一笔。
- **峰位定位**：报峰位与峰值，并区分峰在**内部**还是落在**端点**（落在端点说明采样范围
  还没罩住整个峰，那个位置只是边界）。只报看得见的数，**不做物理解释**。

三条红线由脚本逐条盯着：① **不造数**——输入一律从材料里取，凑不齐就如实说缺什么，
**绝不用等间隔坐标硬凑一条曲线再拟合**（那样得到的 R² 是自己造的）；
② **② 只算数不下判断**——四件一律不产出「对得上/对不上」，那归 ③ 站（判定层拿不到原始参数，
结构上没法造数）；③ **清单外不存在**——调用入口与输入装配器都只认注册表。

### 7. 澄清反问：把"系统说不清的地方"变成"问得出口的问题"

有些事系统**永远不该自己猜**——论文到底写没写某个参数、论文与代码不一致时以谁为准、
读图推断的值对不对。系统从审计结果里挑出**值得打扰用户**的问题，分四类：

| 类型 | 触发条件 | 例子 |
| --- | --- | --- |
| 结论待定 | 论文与代码**高风险**不一致 | 『Learning Rate』论文 `1e-4` / 代码 `1e-3`，以哪个为准？ |
| 缺值 | 论文提到、但四条通道都没取到确定值 | 『Input Size』能否补充？ |
| 待核对 | 读图推断的值（图像无法用文本层验证） | 『Dropout』由读图推断，请核对原图 |
| 解析失败 | 文件未能解析、内容未参与审计 | `legacy.py` 语法错误，是否影响结论？ |

三条约束：**只问用户能答且答了有实质帮助的**；**每条问题都带依据**（哪一页 / 哪个文件 / 哪条证据）；
**系统从不替用户填答案**。用户填写的答复会作为**人工确认记录**写进报告，**不自动改写任何结论**。

### 8. 跨任务记忆：只记线索，不记结论

让系统记住「上次在这篇论文里发现了什么」，但有一条**硬边界**：

> **只记线索，不记结论。**
> 可以记：某参数出现在第几页、取值来自哪条通道、哪些参数已确认"论文没给确定值"。
> **绝不记：参数等于多少。**

为什么：一旦记住"这篇论文的 dropout 是 0.1"，下次审另一篇时就可能把 `0.1` 安到新论文上。
**线索错了最多浪费一次尝试，结论错了就是伪造证据。**

记忆按**论文指纹**索引（`cache/audit_memory.json`），索引键**只取论文内容、刻意不含代码包**
（记忆里的线索全是论文侧的；早期把代码算进指纹，导致同一篇论文因"这次有没有传代码"
被拆成两条记录）。第二条边界：**记忆不自动改变执行**——同一份材料跑两次结论必须完全一致。

**容量上限到极限时自动"压缩成摘要"，而不是丢弃**：触顶后最旧一批明细折叠为只含统计性
线索的摘要（频次、页码分布），**压缩不等于遗忘**——跨任务统计口径包含摘要。摘要里同样
**只允许有线索**，这条硬边界在压缩路径上同样成立。实测：写入 60 篇 → 明细 40 篇 +
摘要 20 篇 = **合计仍是 60 篇**，且**无任何浮点数、无任何参数取值**。

### 9. 分片并发：把"一次要处理很多条"的活拆开跑

本系统的 LLM **从来不是一次性读全部**——归因时每条结论**单独调用一次**（prompt 里只有
这一条的证据片段），论文解析与代码扫描走确定性内核（逐页 / 逐 AST 文件），**完全不经过大模型**。
真正的痛点是**串行太慢**，于是把「拆分 → 各自独立处理 → 汇总」做成机制：

```
run_sharded(items, worker, max_workers=4)
  ├── 每片独立调用: 上下文互不干扰（一片的输入绝不会流到另一片）
  ├── 一片失败只影响那一片: 记为"未覆盖"，其余片照常 —— 绝不假装看过
  └── 汇总只收结构化结论: 不把原文堆回去，因此不会二次膨胀
```

三条约束：**只改变"怎么调度"、不改变"结论是什么"（保序）**；**单片失败不拖垮全局**；
**并发有上限**（默认 4 路，防打爆 API 限流）。

实测：串行 vs 分片 7 条结论**差异 0 条**；真实 API 下归因提速 **4.07x**，读图提速 **3.89x**；
失败隔离（第 2 片故意抛异常）→ 其余 3 片照常完成。

### 10. 从"报告"到"行动"（第三期）

前两期把「检查」做到了尽头，第三期延伸到「行动」——因为拿到报告的人下一步就是动手复现。

| 步骤 | 做什么 | 产出 |
| --- | --- | --- |
| **3.1 复现准备清单** | 环境依赖、关键超参对照（**每个值都附出处**）、数据准备、待确认事项、已知风险 | `REPRO.md`，页面可直接下载 |
| **3.2 根因追查** | 论文与代码不一致时，顺着代码追查**最终生效**的赋值点 | 一条带 `文件:行号` 的根因路径 |
| **3.3 修复补丁草案** | 基于根因给出 diff 草案 | **只展示，绝不落盘** |

这三件与其它环节**同权**（登记为流水线工具、产物落到 `AuditResult`、报告与界面都看得到）。

**补丁的三条铁律**（3.3 最容易出事，所以闸门最严）：

1. **只出方案，绝不写文件**——本模块只返回字符串。自检：跑完后代码包哈希前后**完全一致**；
2. **只改"值"，不生成新代码**，且**只对配置项**出补丁——`optimizer` / `scheduler` / `model`
   属于「实现选择」，把 `resnet50` 改成 `DETR` 并不等于修好问题，这类一律拒绝并说明理由；
3. **拿不准就不给**——"追不出最终生效点"/"待替换值在该行不唯一"/"论文值是排版形式无法
   转成代码字面量" → 拒绝。**拒绝是一门正式能力。**

### 11. AI 的角色：提议在 AI，盖章在程序

大模型**没有"是/否"判定权**，两条通道都只提议，与第一期「抽取 Agent」完全同构：

| 通道 | AI 提议什么 | 程序盖章（否决权在程序） | 开关 |
| --- | --- | --- | --- |
| **AI 排计划** | 哪些环节本次**不值得跑**（成本判断），逐条给理由 | ① 核心步骤不许跳；② **有代码包就必须扫代码**；③ **依赖级联**：上游被跳则下游一并跳过。越界**当场否决并写进决策表** | 网页端**恒开、无开关**；CLI `llm_planner=True` |
| **AI 给补丁提名目标** | 只在「值本身可信、缺的只是选哪个」的两类拒绝上启用，提名"论文的哪个值对应代码实际在跑的配置、该改在哪一行" | 提名必须**落在已抽到的候选里**（不许凭空造值 / 造位置），再走**与确定性通道完全相同**的机械闸门 | `llm_patch=True` |

产出**必须可区分**：确定性通道推出 → `status="proposed"`；AI 提名且过了盖章 →
`status="proposed-llm"` + `needs_human=True`，报告与界面都带
**⚠️ 目标由 AI 提名，采纳前须人工确认**，并列出程序盖章清单。报告里同时写明一句不能省的话：
**程序只验证了「这个值确实写在论文那句里、那一行确实是代码的赋值点、待替换值唯一、
语法与类型合法」，没有验证「它确实属于你要复现的那套配置」。**

> **网页端就是 agent 模式，而且没有开关**：输入材料、点启动，AI 一开始就参与决定跑哪些环节。
> "要不要 AI"不作为选项存在——**AI 参与就是默认行为本身**；AI 不可用时自动回退规则版
> **并如实说明**，不会假装 AI 排过。
> 函数级默认仍是 `False`：CLI 与验证脚本需要**可预测的确定性基线**，
> **agent 模式是"产品默认"，不是"库默认"。**

### 12. 多智能体对撞：让三条独立通道互相挑错

单通道审计有个天然弱点：**同一个抽取器犯的错，它自己查不出来**。所以加了一个「对撞区」——
三条通道各自独立抽取，再把结论摆到一起互相质证：

| 环节 | 做什么 |
| --- | --- |
| 三方独立抽取 | 三个角色（方法 / 实验 / 复现）**各自只看自己那一份材料** |
| 结论对撞 | 逐参数比对：一致记「互证」，不一致记「分歧」（**如实并列，绝不静默覆盖**） |
| 仲裁 | 对分歧给出倾向与理由，并标注置信度 |
| 红队 | 专职找「结论站不住脚」的地方，独立于前三方 |

两条设计红线：

1. **上下文隔离是代码层强制的**——每个角色只读自己那一个视图字段，不是靠提示词约束；
2. **双路核对 = 基线 ∪ 对撞**，基线优先。演示数据实测：**互证 9 条、真分歧 2 条**
   （`scheduler` / `seed`），两路不一致的地方一条都没被抹掉。

> 三类角色可选接模型，但**只做「规范化」**——比如论文写「余弦退火」、代码写
> `CosineAnnealingLR`，统一成 `cosine`；规则版行为一字不变。模型不可用时自动回退，
> 并把原因写进记录，不假装模型说过话。

### 13. 复现闭环：搜 / 算 / 做 + 迭代回边（纯规则、离线可跑、零成本）

审计只回答「哪里对不上」，不等于「能不能复现出来」。这一段补上从「对不上」到「怎么办」：

| 能力 | 做什么 | 硬边界 |
| --- | --- | --- |
| **搜** | 每条结论回原文页码 / 代码 `file:line` 取一手证据；另并发查 **6 个公开学术索引**，给出可点开的外部候选文献（免费、无 key） | 外部文献一律标「未核验」：**文献真实存在 ≠ 它支持这条结论**，后者只能人读 |
| **算** | 把论文与代码的数字互相复算（关系式 + 量纲核验） | 只做小规模，不跑训练；**白名单 ast 求值**，拒绝函数调用 / 变量名 |
| **做** | 生成 7 步复现方案 + **可复现性评级 A/B/C/D**（逐条扣分可查） | 按固定规则扣分，同一参数只扣最重一次 |
| **迭代回边** | 对不上的项：定位根因 → 给修正草案 → 复验，最多 3 轮 | 修正**只在内存推演**，绝不写文件、绝不改用户代码 |

**收敛判据不是「把数字改成一样」，而是「这事能不能真落地」**——根因定到唯一生效点 +
补丁给得出来 + 复验冲突消失，三者齐备才算收敛。第 3 轮属于「换复现目标」的观察轮，
**强制不计入收敛**（否则收敛率永远 100%，没有意义）。

四块全是**纯规则、不调模型**，因此可以做「关掉它结论不变」的消融对照——实测同一份演示材料，
**单路径 / 多智能体 / 多智能体+闭环 三版 11 条结论逐条一致**，闭环链 20 个节点全绿、0 失败。

### 14. 协议化：MCP / Agent Skills 双封装（本地已可调用，暂未对外发布）

同一套审计能力，除网页端外还提供**协议化入口**——不改结论，只换调用方式：

| 形态 | 面向 | 入口 | 对外提供什么 |
| --- | --- | --- | --- |
| **MCP / SCP 服务** | 智能体 ↔ 工具 | `python serve_mcp.py`（stdio）／`--http`（Streamable HTTP） | **10 个工具按四站挂靠**：① 假设 `check_parameters` · ② 实验 `compute_verify` / `science_calc` · ③ 验证 `citation_check` / `literature_search` / `chem_check` · ④ 迭代 `build_repro_plan` / `iterate_fix` · 全流程 `audit_paper` · 清单 `list_pipeline_tools` |
| **Agent Skills 技能包** | 智能体 ↔ 能力包 | `skills/paper2lab-audit/`（SKILL.md + 3 份参考文档 + 3 个脚本） | 按端砚规范组织的自包含能力包；打包器 `tools/pack_skill.py` 带**规范 / 密钥 / 结构**三道闸门，任一不过就拒绝出包 |

**三条如实声明**（答辩会问，先写在这里）：

1. **封装不改结论**——该模块只做「校验 → 调用 → 摘要」，业务逻辑仍只在流水线与图里。
   有测试断言：**主程序路径与 MCP 路径跑同一份材料，11 条结论逐条一致**。
2. **暂不对外发布**——服务默认只监听 `127.0.0.1` 且**不自带鉴权**；若将来发布，
   鉴权与出网策略由部署层负责。当前状态：本地可被任意 MCP 客户端调用，**未上架任何平台**。
3. **依赖是可选的**——`mcp` **不并进** `requirements.txt`（网页端不需要它），单列在
   `requirements-mcp.txt` 并钉 `>=1.0,<2`（2.x 改了 `FastMCP` 接口，与平台示例不一致）；
   装不上也不影响主程序，只在 `serve_mcp.py` 启动时才被导入。

> 对外工具是**按四站挂靠**的 10 个，不是把内部 14 件工序原样摆出去——工序之间靠共享状态串联，
> 单独暴露不可用。14 件工序由 `list_pipeline_tools` 如实登记（每件带 `station` 归属站），
> 另由 `stations` 给出四站全景：**每站入什么 / 出什么 / 哪个对外工具负责 / ② 站挂着哪些具名计算工具**。
>
> **② 只出数、③ 才判定**：`compute_verify` 与 `science_calc` 的返回里**都没有** verdict 这类字段，
> 别去那里找结论；③ 手上没有 ② 的输入表，所以它的判定是可核验的。
>
> `science_calc`（3D 新增）与 `compute_verify` 的分工：后者跑**写死的那条流程**，
> 前者让你**点名调一件**具名工具（`tool` 选工具、`inputs` 给输入，只发字符串的客户端用
> `inputs_json`）。四件工具全部同源于 `scifuncs.SCI_TOOLS`，不在 MCP 侧另抄一份名单。
>
> `literature_search`（4A 新增）是**唯一不需要论文与代码**的工具，只要一个 `query`：
> 在 6 个公开学术索引（openalex / crossref / europepmc / arxiv / datacite / doaj）里并发查，
> 按 DOI 去重、按命中率排序，**全部免费、无需 key**。它证明"这篇文献真实存在"，
> 但 `verified` 恒为 `False` —— "它是否支持你的结论"只能人读，这一点是硬边界。

### 15. 评测打磨：自建审计考卷 + 契约对齐司南（SciEvalKit）

前面所有验证都是**断言型**（该通过就通过）。但"抓错准不准、漏不漏、稳不稳"
需要一个**可横向比较的刻度**。

**接口用书生的、题目用自己的。** 书生的科学智能评测工具链是
**SciEvalKit**（结果同步 OpenCompass 司南榜单）。它评的是"会不会做科研题"，
榜单里没有"审计"这类任务 —— 所以：

- **契约对齐**：`paper2lab/evalsuite/scieval_compat.py` 逐字复刻它的
  `AgentBase / EvalSample / EvalResult / TrajectoryStore` 与 dataset 钩子
  （`tests/verify_eval.py` **直接读官方源码**做签名比对），因此可被它的
  `agent_runner.py` 直接拉起；
- **自建考卷**：5 套真实 arXiv 论文 + 官方代码，另有演示样本、比赛数学建模题与诱饵样本，
  期望项依据各论文**公开超参**人工整理 —— 不是从本工具输出抄的，避免自证；
- **六项判分**：召回 / 精度 / F1 / 自证率，外加**诱饵误报**
  （"合法差异"被误升级为高风险，是最伤信任的错）与**错位值拒收数**；
- **三档消融（3C）**：按四站口径逐档加能力，看"每多开一站多做了什么"——
  档一只开解析员（读＋比，不算不判）/ 档二加计算员（② 设计并真算，只出数）/
  档三全开加审查员（③ 证据自证与判定）。**测不出来的指标报「—」，绝不填 0**
  （没开这项能力 ≠ 表现很差）；
- **零重依赖**：只用标准库，不拖 torch / vllm，可离线复现、零成本。

```bat
rem 三版同跑对比（换执行器：单路径 / 对撞 / 闭环）
.venv\Scripts\python.exe tools\run_eval.py --agent-mode classic,multagent,closeloop

rem 三档同跑对比（换开了几项能力，3C 的能力曲线）
.venv\Scripts\python.exe tools\run_eval.py --tiers parser,calc,review
```

> 档位是**真跳过**（执行记录里 `status=skipped` 并附统一理由），不是把输出藏起来；
> 「抽取 / 比对 / 报告」三件是底座，任何档位都不许跳（代码里是断言，不是注释）。

口径说明与"挂进真 SciEvalKit 的三步"见 `docs/eval-spec.md`。

## 四、系统架构

### 五层架构

```
用户层      论文 PDF / 代码 ZIP / 实验结果 JSON
数据解析层  PyMuPDF(记页码) / AST(记行号) / 多语言通道 / 图像通道
一致性引擎  数值归一化(1e-4 = 0.0001) + 同义词表 + 规则比对   ← 核心，不依赖 LLM
AI 推理层   LLM 只做风险解释与归因(temperature=0, 缓存兜底)
产品展示层  Streamlit 驾驶舱: 就绪度面板 / 证据链 / 审计报告 / 执行记录
```

**核心原则：确定性问题交给程序验证，复杂归因交给 AI。**

### 审计流水线（15 环节 / 14 件工具）

实际执行顺序（由 `TOOLS` 顺序派生，界面进度条与 `STEPS` 同一份口径）：

```
论文解析 → 图像解析 → 图表解析 → 化学身份核验 → Agent 补漏抽取 → 代码扫描 → 假设生成 → 实验设计与真跑
        → 参数归一化 → 交叉匹配 → 实验结果核验
        → AI 风险归因 → 审计自检 → 根因追查 → 补丁草案 → 生成审计报告
```

十五个进度节点由 **14 件工具**完成（「化学身份核验」是唯一不占进度格的工具），每件工具声明依赖产物 / 产出产物 / 成本 / 覆盖节点；
`STEPS` 与界面文案**由 `len(STEPS)` / `len(TOOLS)` 派生**（不再写死数字，避免加一站就要回来改文案）。

### 发现型假设：从「不一样」到「后果多大」（阶段二 2E）

逐项比对只说「两侧不一样」，读者不知道**不一样有多严重**。这一步把它折成可核算的量：

| 产出 | 回答的问题 | 关键约束 |
| --- | --- | --- |
| **影响量级** | 折成倍数是多少、方向朝哪 | 等效批大小 = 批大小 × 累积步数；学习率该跟着变多少**只报区间**（线性 k 倍 / 平方根 √k 倍两派并存，报单值等于替读者选边） |
| **候选解释** | 这个倍数有几种合理解释、哪条**证据最硬** | 四项可核算打分：有出处 +3 / 复验消失 +3 / 违反量纲 −5 / 改动量小 +2；同分时先列**不把差异解释掉**的那条 |
| **四项核算** | 换口径还算得出吗、什么情况归零、跟论文报的对不对得上 | 多口径（两派各算一遍）· 翻盘（哪个输入一变结论反转）· 边界（影响为零的条件）· 对照（论文报告值 → 复现时应看到什么） |

两条纪律写进数据本身，不只在文档里：

- **叫「证据最硬」，不叫「最优」**。优不优要跑训练比准确率，本项目不跑训练；这里排的是「哪个解释证据更硬」，四项加减分摆出来谁都能重算。对照那一项明确标注「要真跑一次，是核对清单，不是我们给出的结论」。
- **是提示层**：`impact` 不参与 `verdict` / `score` / `rank` / 就绪度，推错也只是多一句话 —— 不会有人照着它去改代码。

八套样本实测（`tests/report_impact_samples.py`）：假设卡 51 张，算得出影响 5 张、标出方向 4 张。
**算不出的 46 张不是失败** —— `dataset` / `optimizer` / `model` 这类分类型参数只有「一样 / 不一样」，本就没有「影响多大」可言。宁可漏，不要错认。

## 七、配置（AI 增强，可选）

不配任何 key 也能跑：系统会**如实回退规则版**并在界面标注「AI 未生效」，不会假装排过。

| 键 | 用途 | 必需性 |
| --- | --- | --- |
| `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` | **模型 API**：任意 OpenAI 兼容模型，负责归因解释 / 排计划 / 补丁提议 | 可选（不配走 Mock） |
| `VISION_API_KEY` / `VISION_BASE_URL` / `VISION_MODEL` | 视觉读图（**仅在模型本身不能读图时才需要**） | 可选 |
| `PAPER2LAB_ACCESS_CODE` | 访问口令（**不设则无门**） | 建议（公网部署时） |
| `PAPER2LAB_LIT` | 外部文献检索开关（`on` 默认 / `off` 关掉，关掉后如实标「未启用」） | 可选 |
| `OPENALEX_API_KEY` | OpenAlex 免费密钥（**只是提高额度**，不给也能用；其余 5 个源完全不需要 key） | 可选 |
| `PAPER2LAB_LIT_TIMEOUT` / `PAPER2LAB_LIT_BUDGET` | 单源超时 / 整体预算（秒，默认 4.5 / 7.0） | 可选 |

三条硬规则：

- **Key 与 Base URL 必须成对填写**——程序**不按 key 前缀猜端点**。猜错会连到错误地址，
  而每个读图区域都要重试等待，表现是"极慢 / 像卡死"，根因极难看出来；
- 页面上**只填一组**（Key / Base URL / 模型名）。填完系统按**模型名自动识别**它是多模态
  还是单模态，并在下方写明「支持的输入类型 + 使用注意事项」——识别错了就改模型名，
  不再有勾选框（一个判定只留一处真相）；
- 多模态 → 读图复用这一组模型 API；单模态 → 本次不读图（图片 / 表格 / 扫描页不参与审计，
  未读区域会列在「审计可信度」页）。想让纯文本模型也读图，再配 `VISION_*` 兜底。

**页面没填时的三级回落**（2026-10-30 定）：程序按下面的顺序找模型。凡是由**程序替你决定**的
那几档，都会把"这次到底用了谁、为什么是它"写在你填的输入框**正下方**——高级设置收起时
也看得见，不用点开猜；而**页面填全这一档不再额外弹提示**（三个框就在正上方，再复述一遍
是噪音，只会白占首屏一行）。

1. **页面三个框都填了** → 直接用页面这套（页面填的永远最优先），**不弹状态卡**；
2. **页面没填（或没填全）→ 探测本机有没有已部署的模型**：默认 `127.0.0.1:8080`
   （桌面「书生本地模型」那个启动器就是它；端口可用 `PAPER2LAB_LOCAL_PORT` 改）。
   探测到就直接用——本机明明有，不该逼用户再去申请云 Key；
3. 本机也没有 → 用 `.env` / Secrets 里配的（页面会写明来源是服务端）；
4. 都没有 → 页面明写**「当前没有可用的 LLM」**，并**自动降级跑完整套链路**
   （解析→对表→判定→自检→报告，不中断、不编造）。同时如实列出代价：
   **调度决策**改由固定规则决定、**归因解释**只剩内置模板、**读图完全不参与**、
   问答只能列已检索事实——准确度与详细程度都会下降。

**只填一半不生效**：三个框要么都填、要么都留空。只填一半会当场提示"缺哪一项"
并**不采用**这半套配置（半套配置只会连错地址或认证失败，静默忽略最伤人）。

配置方式二选一：页面左侧「高级设置」直接填，或写进项目根目录 **`.env`**：

```ini
LLM_API_KEY=sk-xxxx
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat
```

`DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL` 是**向后兼容的老名字**（新名字优先）。
`.streamlit/secrets.toml` 是云端的同级替代（**已列入 .gitignore，绝不入库**）。

**默认不预填服务端密钥**：key 一旦进浏览器就等于对拿到链接的所有人公开。
留空不影响功能（会回落到环境变量 / Secrets）。本机自用可设 `PAPER2LAB_PREFILL_KEYS=1`
让页面直接带出 `.env` 里的值——页面会明写"仅限本机自用"，**上线前必须设回 `0`**。

## 九、验证与回归：两层验证，缺一不可

这个项目吃过一次教训，因此把验证固定成两层：

| 层 | 做什么 | 覆盖什么 | 局限 |
| --- | --- | --- | --- |
| **单元级** | 针对刚改的那一处写专项脚本（消融对比、等价重构、并发一致性…） | 改动本身是否正确 | **作者自己写的脚本会顺手传对参数，从而绕开真实调用路径** |
| **端到端** | 像用户一样调用，跑真实样本的完整流程 | 真实路径能否走通 | 慢，不适合定位细节 |

> **为什么两层都要**：曾有一晚 3 个缺陷——规划调度误判"未配置读图通道"而跳过图像解析、
> 抽取 Agent 因拿不到 LLM key 导致补漏整级失效、读图待确认清单把列表当单对象——
> 在**单元级全绿**的情况下依然存在，因为各专项脚本都自己传了 key，恰好绕开了出问题的
> 那条分支。**端到端一跑才全部暴露。**
> 打个比方：**零件测试替代不了路试。**

### 一条主动收回的结论（诚实声明）

DeiT 的 batch 与学习率，**论文其实是给了的**（就在那张两列表里，DeiT-B 列是 `1024` 与
`0.0005 × batchsize/512` 这种带公式的写法）。系统现在把这两项标成「未取到」而非「不一致」，
**不是能力提升，而是把一个不诚实的结果收回**——从多列对比表里挑一个值本来就不可靠，
宁可说"没取到，请人工看那张表"。这与「宁可不报一个值」「宁可不给补丁」是同一条原则。

## 十一、边界与不做的

**不做（防范围失控）**：不跑真实训练 · 不做登录 / 数据库 · 不从曲线图里"反推数值"
（即使 OCR 也难可靠，且价值低）· 图像通道只做"参数与配置"的读取。

**免责**：只审「配置是否一致」，不判断方法本身好不好；论文没给的一律不猜；
工具输出为审计结论与复现清单，**不构成对论文有效性的评价**。

**已知软肋（如实列出）**：语义级方法审计未做 · 读图有固有波动 · 多列对比表目前"整张判为
不可信"（而非取某一列）· LLM 归因文字**不保证逐字可复现**（但审计结论完全可复现——
结论由确定性内核产出，LLM 只负责解释文字）。
