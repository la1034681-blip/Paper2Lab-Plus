# 论文 x 代码 复现一致性审计

## 这个技能解决什么问题

拿到一篇论文和一份「作者自己的实现」或「复现者的开源实现」，
最费时间的不是读论文，而是**逐项核对两边的实验参数到底对不对得上**：
学习率是 1e-4 还是 0.001、batch size 是 32 还是 64、随机种子固定了没有、
数据集是 CIFAR-10 还是某个 v2 版本……

本技能把这件事做成**四个工位接力**，一句「提 → 做 → 判 → 改」：
上一站的产出就是下一站的入场券，每一步都能指认「这个东西是谁给的」。

## 四站主干（用之前先看懂这张表）

| 站 | 入什么 | 出什么（交接物） | 谁负责（MCP 工具） |
| --- | --- | --- | --- |
| ① 假设站 | 原始材料：论文 PDF ＋ 代码包 | **假设卡**：哪几项可疑 ＋ 每项怎么证伪 | `check_parameters` |
| ② 实验站 | 假设卡里推不掉的那些项 | **实验卡**：设计 ＋ 真跑的输入/输出/耗时，**只出数、不下结论** | `compute_verify`（跑固定流程）、`science_calc`（点名调一件工具） |
| ③ 验证站 | 实验卡里的实际值 | **判定卡**：对得上 / 对不上 / 本次判不了，**自己不造数** | `citation_check`（核出处）、`literature_search`（找外部依据）、`chem_check`（核化学身份） |
| ④ 迭代站 | 判定卡里「对不上」的那些项 | 报告 ＋ 修正建议（草案） | `build_repro_plan`、`iterate_fix` |

两个跨站工具：`audit_paper` 一次贯通四站；`list_pipeline_tools` 给出四站全景
（每站入什么、出什么、② 站还挂着哪些具名计算工具）。

`science_calc` 是②站的**点名单**：`tool` 选一件（`fp16_precision` / `series_stats` /
`linear_fit` / `peak_pick`），`inputs` 给输入（只发字符串的客户端用 `inputs_json`）。
它和 `compute_verify` 的区别是**你说了算**——跑哪件、喂什么数由你定，
而 `compute_verify` 跑的是写死的那条流程。

`literature_search` 是③站的**外部文献入口**，也是唯一**不需要论文和代码**的工具
（只要一个 `query`）。它在 6 个公开学术索引里并发查：openalex / crossref /
europepmc / arxiv / datacite / doaj，按 DOI 去重、按标题与摘要的命中率排序。
返回的每条都带 DOI 或落地页，**点开就能核**。

但要注意它只做到两件事：证明**这篇文献真实存在**、给出**关键词层面的相关**。
"它是否支持你这条结论"机器不判，`verified` 恒为 `False` —— 引用前请自己读摘要。

`chem_check` 是③站的**化学身份入口**：抽论文里写的分子式 / CAS / SMILES / 分子量，
再用化学规则**自己算一遍**对账 —— 分子式按 IUPAC 原子量算分子量（判据取论文自己给的
小数位）、CAS 验校验位、SMILES 体检语法。给 `pdf_path` 读整篇，或给 `text` 只核一段原文。

它**刻意不看图认结构**：从像素猜原子和键是幻觉重灾区，看错一个取代基整条结论就废。
所以它只回答"这个式子/这个号/这个质量对不对得上"，**不给化合物命名、不做结构鉴定**。

**为什么②和③要分开**：自己算的数自己下结论，等于自己判自己的卷。
拆开之后 ③ 手上**没有②用的那份参数表**，所以它想编也编不出来 ——
不是纪律要求，是结构上做不到。

## 什么时候用

**该用**（出现下列任一情形）：

- 用户给出一篇论文（PDF）和一份代码（zip 或目录），问能不能复现 / 哪里对不上；
- 用户问「论文与代码的参数是否一致」「帮我做一次复现审计」；
- 用户想评估一份开源实现的可复现性，要一份「照做就能跑」的步骤清单；
- 用户需要为每条差异找到原文出处（写复现报告、答辩、审稿）。

**不该用**：

- 只有论文、没有代码 —— 本技能的核心是**两边比对**，单侧材料请改用论文阅读类能力；
- 非机器学习 / 深度学习领域的论文（本技能目前只在该领域校验过参数语义）；
- 想跑训练来验证结论 —— 本技能**不执行任何用户代码**（见下方边界第 2 条）。

## 输入

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 论文 | 文件路径 | 是 | `.pdf`，最好是可选中文本的版本；扫描件会降级为图像通道，结论会如实标注 |
| 代码 | 路径 | 是 | `.zip` 压缩包，或已解压的目录 |
| 实测结果 | 文件路径 | 否 | 可选的 `results.json`，提供后会把「论文宣称指标 vs 实测指标」一并核验 |
| 模式 | 枚举 | 否 | `classic`（默认，最快）/ `multagent`（多智能体对撞，结论更全） |
| 闭环 | 布尔 | 否 | 是否追加 ② 算 / ③ 核验 / ④ 方案与迭代回边（四站贯通），默认关 |

## 怎么执行（照四站走）

### 第 1 步 · ① 假设站：先出假设卡

只回答「哪几个参数对不上、证据在哪」，最省时间，也最快能判断这份材料值不值得细看。
产出的是一张**可疑项清单**，不是最终结论 —— 每项都标了它凭什么可疑、怎么才能推翻它。
如果清单本来就是空的（两边一致），后面几站通常不用跑。

### 第 2 步 · ② 实验站：对推不掉的项真算

走「算」。它会挑合适的具名计算工具（关系式复算 / 单位展开 / 浮点精度 / 序列统计 /
直线拟合 / 峰位定位等）真跑一遍，留下输入、输出与耗时。
**这一站只交数**：「按论文设置算出来是 0.021，代码里是 0.030」。
它不会说「所以有问题」—— 那是下一站的事。

### 第 3 步 · ③ 验证站：拿实际值下判定

走「搜」做核验：每条结论回原文找出处（论文页优先，其次代码 `文件:行号`），
再判这段出处到底支不支持该结论。判不到就如实写「本次判不了」，
**不会替你补一个数**。

### 第 4 步 · ④ 迭代站：出方案与修正建议

- 要一份**可执行方案 + 可复现性评分**：走「做」；
- 想让它**自己找根因并给修正草案**：走「迭代回边」（有界，最多 3 轮）。

### 呈现结果

给用户的内容里必须**带着出处**，并且**分歧要如实并列**，不要替用户做取舍。
已知会被报出来的分歧类型见 `references/parameters.md` 末尾。

## 输出长什么样

一份审计摘要，包含：

- **统计**：共核对多少项、其中一致 / 不一致 / 单侧缺失各几项；
- **逐条结论**：参数名、论文侧的值 + 页码、代码侧的值 + 文件与行号、状态、风险等级、置信级；
- **每条的来源标注**：这个数是 ② 算的还是 ③ 判的，写清楚（未算的条目不冒充）；
- **就绪度**：0-100 的分维度评分（环境 / 数据集 / 参数 / 实验记录 / 结果一致性），
  没核验的维度**如实标注「未核验」而不是给满分**；
- **自检**：证据自证通过了几条（每条结论的原文片段是否真的包含所述的值）；
- **（可选）** 引证覆盖率、量纲提示、七步复现方案与 A/B/C/D 评级、逐轮迭代留痕。

## 四条边界（回答用户时必须照实说明）

1. **只读，绝不改任何文件。** 迭代回边里的「修正」只是内存中的反事实推演，
   不会写进用户的代码或论文。
2. **不执行用户代码。** 「算」走白名单表达式求值（只认数字与四则运算），
   要 GPU 的训练类复现一律标注「需实机验证」，不会静默假装跑过。
3. **有界自主。** 迭代回边最多 3 轮，第 3 轮是「换一个复现目标再看」的观察轮，
   **不计入收敛** —— 否则收敛率永远是 100%，那种数字没有意义。
4. **外部检索默认关闭。** 若启用，返回的外部线索一律标记「未核验」，
   不得当作出自论文的引证使用。

## 快速开始

```bash
# 1) 环境自检（会告诉你缺什么）
python scripts/check_env.py

# 2) 只跑 ① 假设站（最小核对）
python scripts/audit.py 论文.pdf 代码.zip

# 3) 四站贯通（含 ② 算 / ③ 核验 / ④ 方案与迭代）
python scripts/audit.py 论文.pdf 代码.zip --mode multagent --loop --pretty
```

若提示找不到 `paper2lab` 包，设置环境变量指向项目根目录后重试：

```bash
export PAPER2LAB_ROOT=/path/to/paper2lab      # Windows: set PAPER2LAB_ROOT=D:\path\to\paper2lab
```
